# opencode-editor

Local web editor for `opencode.db` — modify session history and session context,
then resume the session in opencode with the edited context loaded.

## Run

```sh
cd ~/software/my-code/opencode-editor
~/.bun/bin/bun src/server.ts
# → http://localhost:4097
```

Env:

| var | effect |
|---|---|
| `PORT` | default `4097` (opencode uses 4096) |
| `OPENCODE_DB` | override db path (`:memory:`, absolute, or relative to data dir) |
| `XDG_DATA_HOME` | base data dir (default `~/.local/share/opencode`) |

## What it edits (opencode 1.18.x = V1 runtime)

* `session` — title, agent, cost/token counters, archive flag.
* `message.data` / `part.data` — full JSON editing with type validation.
  Part `type` cannot change via edit (delete + recreate instead).
* Compaction — insert marker (`tail_start_id` from the tail estimator),
  remove latest marker + summary (= uncompact). The summary itself is
  generated by opencode when you resume the session.
* `todo` — replace list.
* V2 tables (`session_message`, `session_input`, `session_context_epoch`) —
  read + epoch create/edit/clear. Empty on 1.x; the V1 runner ignores them.

The **Model context** tab shows the projected request
(`filterCompacted` port of `message-v2.ts` + `len(JSON)/4` token estimate):
what the model actually receives vs the full durable transcript.

## Safety

* Every write runs in an IMMEDIATE transaction with `busy_timeout=5000`,
  so it coexists with a running opencode (503 + retry on lock contention).
* Auto-backup via `VACUUM INTO editor-backups/` (throttled to one per 15 min,
  keeps latest 10). Restore from the header (do it with opencode closed).
* Optimistic concurrency: edits send `expectedUpdated`; a 409 means
  the row changed since load — reload and retry.
* New ids match opencode shape (`ses_/msg_/prt_` + 26 chars).
